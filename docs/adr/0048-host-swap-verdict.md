# ADR-0048: 换宿主裁定——VB UI 全面切换 sable-ui(GPUI)双宿主并行

- 状态:**已裁定并执行中**(R0 自 2026-10-04 动工;本 ADR 记录决策、依据与 R0 口径修正)
- 取代:14 篇 Q5「留在 egui」的裁定;22 篇 §3/§4 为执行纲领

## 1. 决策

UI 组件库整体切换到自有项目 sable-ui(GPUI 0.2.2 + gpui-component 0.5.1 + Vello 0.10,wgpu 29,rev 锁定 `72d83c6`,与 cutforge 同锁)。迁移方式为**双宿主并行**:新宿主 `vb_shell`(+`vb_kit` 面板与控件)+ 宿主无关 `vb_session`,旧宿主 `vb_app`(egui)冻结只修 P0,门禁全绿满足 G-SWITCH 后切默认,R7 删除旧宿主。

## 2. 依据(推翻 14 篇 Q5 的三点前提变化)

1. gpui 0.2.2 已上 crates.io 正式版;gpui-component 0.5.1 是最后绑定 gpui ^0.2.2 的稳定线。
2. cutforge 桌面壳已用 sable 全栈生产接入并多轮迭代(rev 72d83c6 起)——"生态不成熟"不再成立。
3. egui 天花板实锤:无自定义光标图、无合成层、画布文本近似(X-2)、截图纹理 4096 上限、焦点体系全手搓。
4. 上屏通道最大未知数已由 ADR-0047 spike 消解(GPUI 原生翻译层主线)。

## 3. R0 口径修正(对 22 篇 §4 R0 交付 4 的诚实化)

「run_command 原样搬家」**修正为**:R0 落 `vb_session::command` 命令信封(CommandId 校验/请求与结果类型)+ `Dispatcher` trait 边界,vb_app 提供实现;**新宿主实际经 Dispatcher 执行文档命令推迟到 R1**(届时新宿主有自己的 session 可被分发;旧宿主独有的 run_command 全量 match 属 vb_app 域,不属可提取的宿主无关逻辑)。理由:双宿主不能同进程共享会话,把 31k 行 vb_app 的中央分发整体搬到 vb_session 既不可行也不必要;强行搬家=变相整体迁移,违背 R0「脚手架」定位。

## 4. DROP 门禁修订裁决(22 篇 §10 悬案)

新增 DROP-3(架构原则冲突类:节点图文档模型/状态机动效/内置生成式 AI/实时协作光标)。**裁决:Dropped 门禁由「总数 ≤2」改为「按类别记账,总数 ≤5,每条必须标注冲突的具体原则」**;DROP-1(渲染能力类)/DROP-2(云服务类)编号不变。落地于 capabilities 数据模型与既有 `dropped_discipline` 测试。

## 5. 后果

- 正面:真文本管线、自定义光标、Mica、三层动画引擎、焦点体系全量;4096 上限结构性消解(ADR-0047 路线 (c) 无整幅纹理)。
- 代价:29+ 面板重写(R2)、迁移期双宿主 CI、ACL-1.0 规程纪律(22 篇 §3.5)。
- 风险回收:任何一轮不绿 → `--host=egui` 回退;旧宿主删除前一直在 git 历史。
