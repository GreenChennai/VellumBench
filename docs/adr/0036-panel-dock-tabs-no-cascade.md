# ADR-0036: 面板默认停靠进 Tab 坞,保留浮动但禁止级联

- 状态:已接受(阶段 4b / 副文档 04-2;兑付迭代附录 ADR-VB-L04,主文档 W5/W8)
- 背景:实测 P0-⑥ 七个面板以浮窗级联堆叠、最多遮挡约 1/4 画布,与
  ADR-0024「面板保持停靠、不浮动」的精神冲突 —— 面板容器缺公共实现,
  各面板各画各的浮窗。
- 决策:
  1. 新增**次级面板坞**(`SecDockState`):九面板默认按组停靠为 Tab
     (文字组 / 外观组 / 变换组等),Tab 顺序 / 折叠态入 `workspace.json`
     持久化(ADR-0029 承接);
  2. **保留浮动能力**但默认关闭,且浮动窗由统一容器管理 ——
     门禁测试断言:七面板全开时浮窗互不覆盖(`never_cascade`)、
     停靠模式画布可见面积损失在约定上限内(`loss_within_cap`);
  3. **自研坞容器,不引 egui_dock**(主文档 W8):与 ADR-0023/0024 的
     既有停靠底座同源,不为"拖拽重组"引入新依赖。
- 落地:`crates/vb_app/src/app/panel_dock.rs`(坞状态机 + 两条遮挡门禁测试)、
  `crates/vb_app/src/app/panels/mod.rs`(统一入口)。
- 取舍:牺牲"随手一拖就浮窗"的自由;换来画布可用与面板布局可持久化。
- 被否决替代:(a) 维持级联浮窗(实测不可用);(b) 引 egui_dock
  (能力过剩、增依赖、与自研工具栏停靠并存两套心智)。
