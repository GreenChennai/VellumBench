# ADR-0024: 面板保持固定停靠,不做浮动(承接 design/14 F8)

- 状态:已采纳(承接既有决策;2026-09-21 复核确认未被打破)
- 背景:`design/14:240` 的 F8 已裁定「面板固定停靠,不做浮动」。目标⑥新提的
  "工具栏可停靠"容易被误读成"面板也可以浮动",需要在 ADR 层把两者切开。
- 决策:
  1. 右侧面板坞只做「**可折叠为图标条 + Tab 分组**」,不做浮动窗口 / 拖拽重组;
  2. 工具箱的停靠(ADR-0023)与面板坞**互不影响**:面板坞始终是 `Panel::right`,
     工具箱可以是四向中的任意一向;
  3. 浮窗仅限于**工具型面板**(字符/段落/外观/描边/渐变/透明度/颜色/变换/对齐/
     能力台账)—— 它们由命令显隐,不参与停靠系统。
- 实现:`crates/vb_app/src/app/panels/mod.rs` 只有 `dock_rail`(40px 图标条)与
  `dock_expanded`(280,可拖 240–420)两个固定 `Panel::right`,全库无面板浮动窗口。
- 验证:步骤 3(07a 报告)逐字复核 —— 面板坞仍是两个固定 Panel;
  `vb_ui::dock` 的折叠规则是纯函数并有单测。
- 理由:浮动面板会引出"窗口层级 / 重叠遮挡 / 布局持久化爆炸"三类复杂度,
  收益是少数高级用户的自由度;与 AI 的"工作区"模型相比,固定坞 + 工作区预设
  已能覆盖绝大多数场景。
- 后果:若将来要做浮动面板,必须先推翻本 ADR 并重做布局持久化 schema。
- 关联:副文档 02 / 07;ADR-0023(工具可停靠)、ADR-0029(布局持久化)。
