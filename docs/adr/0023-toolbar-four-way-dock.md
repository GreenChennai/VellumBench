# ADR-0023: 工具箱采用四向停靠(DockSide),不引通用 dock 框架

- 状态:已采纳(2026-09-21;副文档 07 V2/V3 决策落地)
- 背景:目标⑥要求工具箱可在**顶/左/右(/底)**吸附固定;此前工具箱是
  `egui::Area` 锚 `CENTER_BOTTOM` 的浮动条(不可移动)。同时 `design/14:240`
  (F8)已裁定「**面板**固定停靠,不做浮动」。另:全库无 dock 机制
  (只有 `theme.rs` 里的"坞"字视觉常量)。
- 决策:
  1. 自研轻量停靠:`enum DockSide { Top, Left, Right, Bottom }` +
     `egui::Panel::{top,bottom,left,right}` 分支,**不引入 `egui_dock`**;
  2. **停靠即吸附,不做浮动**:拖动把手时按"指针到四边的最近距离 ≤ 56px"
     判定吸附边并画预览带;落在中间 → **回弹**(`DockSide::nearest` 返回 `None`);
  3. 左/右停靠可切**单列(60)/ 双列(88)**;顶/底恒单行(高 = 控制条同高);
  4. **装配次序 = 层级规矩**:菜单栏(最先,最顶)→ 控制面板 → 顶/左/右向工具箱
     → 右侧面板坞 → **状态栏(底向最先装者最外)** → 底向工具箱 → 画布。
     egui 的面板"先装者更靠外",故底向工具箱必须装在状态栏**之后**,
     状态栏才能永远贴底。
- 实现:`crates/vb_app/src/app/dock_layout.rs`(纯几何/持久化)、
  `crates/vb_app/src/app/toolbar.rs`(渲染 + 拖动吸附 + 同族展开)。
  停靠位切换有 6 条命令(`view.dock_toolbar_{top,left,right,bottom}` /
  `view.toolbar_columns_{1,2}`),进「窗口」菜单,可被 Agent 复现。
- 验证(2026-09-21 机器实测):
  - `dock_layout::tests` 10 例:边缘吸附 / **中间回弹** / 角上取更近边 /
    四向尺寸 / 列数钳制 / 配置读写与损坏回退;
  - `toolbox_groups.rs` 4 例:选择与直接选择是两个独立工具(V/A、图标、紧邻)/
    同族族内自洽 / 单成员族不出菜单;
  - `workspace_persist.rs` 2 例:经真实路径写入 → 重新 `load` 逐字段还原;
    损坏文件回退默认 + 告警。
- 理由:四向 + 吸附是**目标⑥的最小完备集**;引 `egui_dock` 会与 F8 的
  "面板不浮动"精神打架,且为"拖动重组"这类我们不需要的能力付出依赖与
  调试成本。停靠位/列数是**布局状态**,天然属于"工作区",于是顺带把
  `workspace.json` 一并落地(见 ADR-0029)。
- 后果:工具栏新增位置时必须先在本 ADR 的枚举里登记;`DockSide` 是
  `workspace.json` 的序列化契约(`snake_case`),改名即破坏兼容。
  与 ADR-0024(面板不浮动)不冲突:**工具 ≠ 面板**。
- 关联:副文档 07;ADR-0024(面板固定停靠)、ADR-0029(布局持久化)。
