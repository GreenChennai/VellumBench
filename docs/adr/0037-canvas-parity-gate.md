# ADR-0037: 新增画布↔导出像素一致性门禁(canvas_parity)

- 状态:已接受(阶段 3 / 03-3;兑付迭代附录 ADR-VB-L05,主文档 W7)
- 背景:实测 P0-③"画布第二个画板被裁掉(CSS 声明 520px,画布只见 ~182px),
  CPU 导出却正确" —— 画布与导出是两条渲染路径,没有门禁就必然复发。
- 决策:
  1. 新增隐藏出图通道 `vellumbench --project <dir> --canvas-shot <out.png>
     --artboard <sid>`:启动后第 20 帧**按固定标称框**对准目标画板(不读
     当前画布矩形 —— 否则缺陷被相机缩放补偿掩盖),并把窗口从 1680×1000
     增大到 2200×1200(增长本身即探针:画布矩形若不随窗口增长,GPU 纹理
     停在旧尺寸,画板必放不全),第 50 帧把**画布同款 GPU 纹理**读回落盘
     + manifest JSON(画板尺寸 / 缩放 / 裁剪矩形 / 是否完整);
  2. `tools/canvas_parity.ps1` 对拍:**硬判据** = 画板完整可见 + 画板矩形
     与导出 PNG 换算尺寸一致(≤1px),直接拦截;**软判据** = 像素相似度
     分数,只报告不拦截;
  3. 接入 ci.ps1 门禁 11(全量档);无头 CI 走轻量档跳过(需 GPU + 窗口)。
- 落地:`crates/vb_app/src/canvas_shot.rs`(出图状态机)、
  `tools/canvas_parity.ps1`(对拍脚本)、`tools/ci.ps1`(门禁 11)。
- 取舍:门禁需要维护 + CI 时间(重门禁分档);换来"画布可信"。
- 被否决替代:只修 bug 不加门禁(P0-③ 证明必然复发)。
