# ADR-0022: 导出路线按格式显式分化,保真主路不得被矢量路线静默接管

- 状态:已采纳(2026-09-19,由 Kiln 迭代指导书 v1.0 提出,同日实现)
- 背景:提交 14a81dd 把 `"PNG"` 纳入 `want_dom` 白名单(默认 `--vector auto`),
  使光栅格式改走「浏览器布局 + Kiln 栅格」,G1 由平均 99.93 跌至 93.94
  (最差 99.65 → 82.46)。同基线同二进制的消融对拍证明 `--vector chrome`
  可逐例复现历史分数(4 静态例精确到小数点后两位),G1 回归 100% 由路线
  切换解释、无其他混杂因子(指导书 §2.2/§9.3.3)。
- 决策:
  1. 每个导出格式必须有**显式的期望路线表**(格式 → 主路线 → 退路),
     `auto` 只按表放行,不得隐式决定光栅格式的路线。
  2. 期望路线表(本 ADR 的规范附件,门禁与报告以此为断言输入):

     | 格式 | 主路线 | 退路 | 理由 |
     |---|---|---|---|
     | PNG/JPG | `chrome`(浏览器原生截屏) | 车道 K | 像素保真最大;历史 G1 99.9 只在 chrome 复现 |
     | AI | `dom`(DOM 快照 → Kiln 矢量写入) | printToPDF+AI 头 | 可编辑性:整行 CID 文本/双 OCG/零剪切蒙版 |
     | SVG/EPS | `dom` | 车道 K | 同 AI,真文本矢量语义 |
     | PDF | `dom` | printToPDF | 可编辑 + 渐变位图化兼容(G2/G3/G4 门禁背书);拉丁 base-14 未嵌入为已知边界(K3,列 carry-forward) |

  3. 报告 JSON 必须携带实际生效路线(`engine` / `vector` 字段,已有),
     「实际路线 ≠ 期望路线」应在验收门禁判败(路线断言,§9.5 建议 1)。
  4. 显式 `--vector dom` 请求光栅格式时不再静默改道,stderr 发
     `{"warn":"…期望路线为浏览器原生截屏(ADR-0022)…"}` 后按 chrome 执行。
- 实现:`kiln-cli.rs` 路线闸门把 `"PNG"` 移出 `want_dom` 白名单;
  附带 K4 修复(导出副产物 `.kiln-raster`/`.kiln-paintlist.json` 改写系统
  临时目录,导出结束清理,`KILN_KEEP_INTERMEDIATE` 显式保留)。
- 验证(2026-09-19 机器实测):
  - `bench/ai_struct.py` 结构门禁 6/6 通过(零 Type3/零 Shading/SMask 仅挂
    图像、Tj≤行数×1.2、W n=0、OCG=「背景/内容」、pdfium 文本抽取 delta=0
    含 festival-zhongqiu);
  - G1 抽查(qr-poster,festival-zhongqiu,WPI 现渲基线):平均 99.82、
    最差 99.77、尺寸门通过(修复前默认路线平均 93.94);
  - 多画板:a4-front+index_back 双 `--source` → 单 .ai 两页 1240×1754。
- 理由:路线切换同时改变像素保真与可编辑性两个互斥目标;auto 的隐式
  选择让 6 分回归在 26 例全量上静默发生,违反了既定优先级
  「保真度 > 可编辑性 > 转换速度」未被显式表达。
- 后果:新增格式时必须先在本表登记主路线与退路;验收门禁增加路线断言与
  消融能力(M1);与 ADR-0020(双车道)、ADR-0021(DOM 快照写入)不冲突,
  是对其放行范围的精确化。
