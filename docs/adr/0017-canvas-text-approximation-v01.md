# ADR-0017: v0.1 画布内文本用 egui 近似绘制;原生文本管线属 v0.2

- 状态:已接受(2026-09-09,范围控制裁定,关联 R5)
- 背景:路线图 v0.1 明确「不做:文本…」;但导入的 HTML 仍含 `<p>`/`<h1>` 等 Text 节点,画布不能"点了没反应"。
- 决策:v0.1 画布把 Text 节点以其字体样式近似绘制(egui 字体栈,含系统 CJK 字体回退);位置/颜色/字号正确,字形度量与浏览器有差。**HTML 导出与 CLI 输出一律是真实文本**,近似只存在于编辑态画布。v0.2 接入 Parley/Swash 后移除近似路径。
- 理由:Parley 文本管线是 v0.2 的整块工程,提前塞进 v0.1 违反"每版可交付"铁律;近似绘制让导入文档在 v0.1 就"可看、可挪、可改属性"。
- 后果:编辑态所见与浏览器在文本字形上有可感差异(v0.1 已知限制,写入 README);CPU/GPU 导出引擎 v0.1 对文本画占位框并列 warnings(见 ADR-0016)。

---

## 复议(2026-09-13,15 号计划 C4 兑付)

- **状态:部分兑付。** CPU 导出(CLI/CI)已由「占位条」升级为**真字形**:
  fontique 字体发现 → swash 整形(单一引擎,cmap+字距)→ swash scale
  轮廓 → kurbo 路径 → tiny-skia 填充。中英文均可,回归测试
  `text_renders_real_glyphs` 锁定(多行墨迹覆盖 + 无占位警告)。
- **画布侧维持 egui 近似不变**:egui 自身渲染的是真文本(可读、可编辑),
  与浏览器字形度量的可感差异仍在 —— 该差异的消除需要统一布局引擎,
  归 Parley 完整接入(多行/双向),见下方改口。
- **工程改口**:本 ADR 原文「v0.2 接入 Parley/Swash 后移除近似路径」。
  实测裁定:CPU 导出真字形用 **fontique + swash 直接管线**(单行文本
  无需 parley 的多行/双向布局;parley 依赖已探明并在需要时再接入),
  swash 的 Han 脚本引擎在部分字体上产出空字形,统一走 Latin 引擎
  (cmap 映射 + 字距,CJK 无复杂整形需求,实测可行)。
- v0.3 已知限制(诚实清单,代码注释同步):
  ① 单字体运行(混合文字取第一个可覆盖全部字符的字体,缺字出
  .notdef),逐字符回退留后续;
  ② LTR 方向,RTL 按 LTR 输出;
  ③ 不自动换行(与画布近似行为一致)。
