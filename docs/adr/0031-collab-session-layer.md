# ADR-0031: 协同为会话合并层(CRDT 仅用于连续属性),文档真相仍是 HTML

- 状态:已接受(阶段 5-G / 05-11-4 / 05-11-5;兑付迭代附录 ADR-VB-L13)
- 背景:协同编辑需要冲突消解。全量 CRDT 文档模型(Automerge/Yrs)会摧毁
  「文件真相源 + HTML 可 diff + 零浏览器依赖」三条不可妥协原则(ADR-0010);
  ADR-0008 曾预留「v3 做协作时为 CRDT 改造(sid 稳定 id 天然适合 CRDT 键)」。
- 决策:协同是**会话合并层**,分四条边界:
  1. **连续属性**(位置 x/y、尺寸 w/h、透明度 opacity)用
     **LWW-Element-State CRDT** 无冲突合并 —— 元素 = `(节点 sid, 属性)`,
     全序 = `(lamport, writer_id)`;合并逐元素取全序最大,可交换/可结合/
     幂等,两端以任意顺序交换任意次必然收敛(单测断言三律)。
  2. **结构性变更**(增删节点/改树)**不走 CRDT** —— 走既有命令底座 +
     三方对比(09-N)+ rev 乐观锁(07-R 外部改动印记 / K3 多写者策略)。
     并发结构冲突仍需用户裁决,换来与现有架构零冲突。
  3. **落盘仍是 canonical HTML**:会话合并只作用于内存文档,导出走
     `export::render_project` 同一序列化(与桌面 Ctrl+S 字节同源);
     收敛判据 = 两端导出文件表字节一致 + 往返 L0/L1 不破(有 e2e)。
  4. **传输 = 本地共享目录**(`.vb-collab/ops-<writer>.json`,tmp+rename
     原子替换,坏文件跳过不静默),不引入云账号、不引入长连接服务。
     选共享目录而非 localhost TCP:实现最简(纯 std::fs,无端口协商与
     生命周期管理),且与「文件是交换介质」的项目气质一致。
- 落地:`crates/vb_doc/src/collab.rs`(`CollabOp` / `CollabState` /
  `SessionWriter` + 传输纯函数;应用走 `Command::SetGeom`/`SetStyle`
  命令路径,rev 随之推进,撤销可精确还原)。
- 取舍:同属性并发时后到者胜(LWW),被覆盖一方无合并提示 —— 连续属性
  (几何/透明度)语义上可接受;结构冲突留给人工裁决。会话层当前为库 API
  + 测试驱动,GUI「启动协同会话」入口未接(台账 09-K K4=Partial 写明)。
- 被否决替代:全量 CRDT 文档模型(风险与收益不匹配,摧毁三原则);
  OT(操作变换,实现复杂度远超 LWW,且同样要动文档模型)。
