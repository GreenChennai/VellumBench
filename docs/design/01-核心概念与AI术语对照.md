# 01 · 核心概念与 Illustrator 术语对照

> "专有名词理解要像 AI" —— 这篇是那条需求的落地。
> 原则：**用户脑子里想的是 AI 的词，界面上显示 AI 的词，鼠标做的是 AI 的动作，落盘时翻译成 HTML 的词。**
> 翻译规则对用户透明但不打扰，需要时可在「代码视图」里查看真实对应关系。

## 二、四个必须解决的翻译难题

### 2.1 描边（Stroke）：AI 与 CSS 的根本冲突

**冲突**：AI 的描边不占布局空间（沿路径居中绘制）；CSS 的 `border` **占布局**（撑大盒子）。

**解决方案（分对象类型）**：

| 对象类型 | 实现 | 代价 |
|---|---|---|
| 矢量路径（svg） | `stroke` + `stroke-width`，可设 `stroke-alignment`（v1 用 path 偏移近似） | 无 |
| 盒对象（div/button/a） | **默认用 `border` + `box-sizing: border-box`** | 盒子外尺寸不变，与 AI 视觉一致；这是 99% 场景的正确选择 |
| 需要"内侧描边" | `box-shadow: inset 0 0 0 Npx color` | 不占空间，不影响 border-radius 以外的布局 |
| 需要"外侧描边" | `outline: Npx solid color`（不参与布局）或负 `margin` | outline 在部分元素上不跟随圆角（现代浏览器已支持跟随） |

**规则**：属性面板的"描边对齐"下拉（居中/内侧/外侧）默认 **居中 = border-box 的 border**，用户不需知道背后的 CSS。
**导出时**：若对象只用了居中描边，输出 `border`；否则输出对应 box-shadow/outline，并在代码视图给出提示。

### 2.2 外观栈（多重填充/描边）

AI 允许一个对象叠加多个填充+描边。CSS 没有直接对应。

**三层策略**（按顺序尝试，能简单就简单）：

| 层数 | 实现方式 |
|---|---|
| 1 层填充 + 1 层描边 | `background` + `border`（最常见，必须干净） |
| 多层填充（纯色/渐变叠加） | `background-image: linear-gradient(…), linear-gradient(…)` （逗号分隔，前面的在上） |
| 多层描边 | 多层 `box-shadow: 0 0 0 Npx color, 0 0 0 Mpx color2` |
| 超出上述能力（如不同混合模式的多层） | 生成 `::before` / `::after` 伪元素层，或直接**降级警告 + 建议栅格化** |

**UI 保持一致**：外观面板长得和 AI 一样（可添加/删除/排序填充与描边条目），用户在 AI 心智下操作，实现细节隐藏。

### 2.3 剪切蒙版 vs overflow

| AI 蒙版类型 | CSS 实现 | 限制 |
|---|---|---|
| 矩形/盒对象作蒙版 | 父元素 `overflow:hidden` | 圆角也生效，完美 |
| 矢量路径作蒙版 | `clip-path: path('M…')` | 兼容性好；复杂路径性能略降 |
| 不透明度蒙版 | `mask-image: linear-gradient(...)` | 与 AI 的 Opacity Mask 对应 |
| 蒙版内含多级嵌套 | 逐层 `overflow:hidden` | 隔离模式下编辑需临时解除 |

### 2.4 变换：AI 矩阵 vs CSS transform

- 二者都是 2D 仿射变换（平移/旋转/缩放/倾斜），**语义一致**，可直接映射。
- 差异：`transform-origin`（AI 参考点）CSS 默认 `50% 50%`，AI 默认也是中心 —— 一致。
- **进入编组编辑时**：AI 会把父级变换带入。Vellum Bench 保持同样行为：编辑子对象时，显示的是应用了祖先变换后的坐标，但**输入数值时用本地坐标**（和 AI 一模一样）。
- **数值精度**：CSS 输出保留最多 4 位小数，末尾 0 去除（`rotate(45deg)` 而非 `rotate(45.0000deg)`）。

## 三、AI Plus：HTML 带来的超能力（产品卖点）

AI 做不到、但 HTML 天然支持的能力。这些要在界面里**显式暴露**，作为"比 AI 更强"的证据。

| 能力 | Vellum Bench 术语 | HTML/CSS | 面板位置 |
|---|---|---|---|
| **设计令牌** | 令牌 / 变量 | `--vb-color-1: #FF5A1F` | 色板面板 → 「变量」分组；改一处全站更新 |
| **自动布局** | 自动布局 | `display:flex; gap:16px` | 属性面板 → 布局分组（v0.7） |
| **响应式断点** | 断点 | `@media (max-width: 768px)` | 画板宽度下拉预设 + 断点切换器（v0.7） |
| **交互态** | 状态（默认/悬停/按下/禁用/聚焦） | `a:hover {…}` | 属性面板顶部状态切换条 |
| **语义标签** | 标签 | `header/nav/main/section/h1/a/button` | 属性面板 → 「标签」下拉（对 SEO/无障碍有价值） |
| **原生文本流** | 文本自动换行 | 默认行为 | 无需设置 |
| **长页面滚动** | 画板高度可超屏 | 默认行为 | 画板高度 > 视口即滚动 |
| **链接与锚点** | 链接 | `<a href>` | 属性面板 → 交互分组 |
| **可访问性属性** | A11y | `alt` / `aria-label` | 属性面板 → 无障碍分组 |

> **设计约束**：这些能力默认**不打扰** AI 用户。例如"标签"下拉默认是 `div`，只有用户主动改才变 `section`。不要为了"正确的 HTML"去教育用户。

## 四、HTML 有、但 AI 概念里没有的东西（需要新术语）

| 概念 | 术语 | 设计决策 |
|---|---|---|
| 冻结块 | **冻结块 Frozen Block** | 含白名单外 CSS 的导入片段。可见（渲染快照）、可移动/缩放/删除、**不可编辑内部**。双击提示"在代码视图中编辑"。图标用雪花❄，状态栏常驻提示。 |
| 响应式约束 | **约束 Constraint** | 借鉴 Figma：左/右/居中/拉伸/缩放。映射到 `margin:auto` / `position` / `flex`。v0.7 引入，属于"AI Plus"而非 AI 原有。 |
| 伪元素 | **装饰层** | 用户不用管，由外观栈自动生成。 |
| 内联 vs 外链 CSS | **样式输出方式** | 设置项：外链 `styles/main.css`（默认）/ `<style>` 内联 / 单文件 HTML。 |

## 五、单位与坐标系统（全局统一，写死）

| 项 | 规定 |
|---|---|
| 内部存储单位 | **px（CSS px，1/96 inch）**，全链路只用 px |
| 显示单位 | 可切换 `px` / `pt` / `mm` / `inch`（偏好设置）。换算：1pt = 4/3 px，1inch = 96px |
| 新建文档默认 | px，画板 1440×900 |
| 坐标原点 | 画布为无限平面，Y 轴**向下**（与 CSS 一致） |
| 画板坐标 | 每个画板有本地坐标（左上角为 0,0），对象坐标存**相对所属画板** |
| 变换表示 | `kurbo::Affine`（2×3），序列化时按 `translate/rotate/scale/skew` 分解输出，保持人类可读 |
| 缩放 | 视图缩放 1%–6400%（与 AI 一致），无单位 |
| 角度 | 0° 为 3 点钟方向，逆时针为正（与 AI 一致）；写入 CSS 时 `rotate()` 顺时针为正 → **输出时取负** |

> ⚠️ **角度陷阱**：AI 与 CSS 的旋转正方向相反。必须在序列化层统一转换，并写单元测试锁死。

## 六、命名规则（AI 名字 ↔ class / id）

用户在图层面板里写的名字（如「主标题」）需要落到 HTML：

```
图层名: 主标题
  ├─ data-vb-name="主标题"        ← 始终写入，供 Agent/回读显示
  ├─ data-vb-id="a7f3c2"          ← 稳定短 id，供 Agent 寻址（永不因改名而变）
  └─ class="hero-title"            ← 由命名策略生成
```

**命名策略**（设置项，默认「语义化」）：

| 策略 | 行为 | 适用 |
|---|---|---|
| 语义化（默认） | 中文名 → 拼音/英文翻译 slug；英文 → kebab-case；冲突加 `-2` | 大多数用户 |
| 保守 | 一律 `vb-el-<id>`，语义只放 `data-vb-name` | 害怕 class 污染的用户 |
| 自定义映射表 | 用户维护 `主标题 → hero-title` 词典 | 团队规范 |

**规则**：
- `id` 属性默认**不生成**（避免污染），只有用户显式勾选「生成 id」或元素是锚点/表单控件时才生成。
- 保留字/非法字符自动清洗；不以数字开头。
- 类名词典随工程存 `.vbdoc/naming.json`。

## 七、术语禁用表（写在 UI 文案规范里，CI 检查）

| ❌ 不要说 | ✅ 要说 | 原因 |
|---|---|---|
| Frame | 编组 / 画板 | Frame 是 Figma 词，AI 用户不熟悉 |
| Component（日常） | 编组 | Component 在 v1 无对应能力，说了会误导 |
| Layer（泛指任何元素） | 对象 / 元素 | Layer 在 AI 里是顶层容器，滥用会让 AI 用户混乱 |
| 组 / Group（混用） | 编组 | 统一 |
| 属性 / Attributes | 属性（可以）；但 HTML 属性说「HTML 属性」 | 避免与 CSS 属性混淆 |
| 样式（指 CSS 时） | 样式；指 AI 图形样式时说「样式/类」 | |
| 画板工具（叫"页面"） | 画板 | 与 AI 一致 |
| 导出为 Web（旧 AI 说法） | 导出 | |
| Slice（泛指） | 切片 | |
| 智能对象 | ❌ 不用 | Photoshop 词 |
