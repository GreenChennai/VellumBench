## 1. 执行摘要

**问题定性:这不是缺陷堆,是一次架构错位。** Kiln v0.6.0 的 PNG 导出走的是"自研 HTML 解析 → 自研布局(taffy)→ 自研光栅(tiny-skia)"全链路,试图在 Rust 里复刻一个浏览器;而用户认定"正常"的 WPI PNG,本质是**系统 Chromium(Edge)本尊渲染**。验收集(§3)大量使用 grid、mask-image、mix-blend-mode、background-clip:text、backdrop-filter、可变字体等自研引擎结构性缺失的特性,因此当前导出在真实工程上"完全不可使用"是**必然结果而非偶然 bug**。同时,已公开宣称的"PDF 保真 98.63"是**自洽对拍分**(Kiln PDF→pdfium vs Kiln 自家 PNG),闭环里没有浏览器真值,数字无法外推到真实保真度。

**方案:双车道导出架构(ADR-0020)。**

- **车道 B(浏览器车道,保真优先,默认)**:kiln-cli 内建 Rust 原生 CDP 客户端,驱动系统 Edge/Chrome——PNG 用 `captureScreenshot`(captureBeyondViewport)完整移植 WPI 十要素捕获协议;PDF/AI 用 `Page.printToPDF`(screen 媒体仿真 + 精确纸张尺寸)得到真文本矢量 PDF,再加后处理。与 WPI 同引擎、同协议,99% 对拍**由构造保证、由夹具验证**。
- **车道 K(自研车道,离线兜底)**:现有 vb_layout/vb_render/vb_kiln 链路保留,服务无浏览器环境与编辑器实时预览,**不再承担对外保真承诺**,导出时显式 WARNING 降级声明。

**验收:全部由新门禁工具 `bench/acceptance.py` 机器出分**(教训:门禁全绿≠功能真实,达成清单必须由对拍夹具生成,不手写)。硬指标:

| 门 | 指标 | 合格线 |
|---|---|---|
| G1 PNG 对拍 | Kiln PNG vs WPI PNG,MAD-score(§5.1) | 平均 ≥99,最差例 ≥98,尺寸 100% 相等 |
| G2 PDF 对拍 | pdfium 渲染 PDF vs 车道 B PNG | 每例 ≥97,平均 ≥98.5 |
| G3 AI 对拍 | AI(=PDF 兼容流)同 G2 | 同 G2 |
| G4 真文本 | PDF 文本抽取 == HTML 源文本 | 逐例全量匹配 |
| G5 字体嵌入 | PDF 内字体 100% 嵌入(含拉丁) | 零未嵌入 |

**六个里程碑**:M1 立尺(验收夹具先行)→ M2 PNG 车道 B → M3 PDF 车道 B → M4 AI 与可编辑性 → M5 长图/多页/动画定格专项 → M6 收口发版(kiln-cli v0.7.0 + artboard 同步)。优先级贯穿用户裁定:**保真度 > 可编辑性 > 转换速度**;不可矢量化的效果按"局部栅格化 + 透明组原位放回"降级(§4.5),这是 Skia SkPDF 与 Adobe 透明拼合器的同款标准做法。

### 2.2 根因:架构错位,而非缺陷堆

- **ADR-0001** 建库即裁定"自研场景图,不内嵌浏览器"——编辑器数据模型自研是对的,但**导出栅格也一并自研**,等于要求 vb_layout+vb_render 达到 Blink+Skia 的像素级复刻。
- **ADR-0005** 曾以"WPI 进程桥"形式保留浏览器渲染(`vb_export/src/wpi.rs`),v1.9.0 换血时被降级为回退,`wpi.rs:52` 还留着硬编码本机绝对路径 `E:\平日资料\GitHub\WPI`,开源环境必然解析失败(`resolve_wpi_dir` 返回 None)。
- 浏览器车道被切断的那一刻,就是 PNG 保真崩塌的那一刻。**修复方向因此不是继续在车道 K 上打补丁,而是把浏览器车道请回主位,且以 Rust 内建、无 Python 依赖的方式(ADR-0020)。**

### 2.3 "98.63" 的真相(数字口径审计)

- `bench/fidelity.py`:score = 100×(1−MAD/255),基线 = WPI 浏览器渲染,达标线 97,历史均分 97.39/95.4(BENCHMARK.md:59,108)——**这才是真实对浏览器保真分,且只有 5 案例小套件**。
- `bench/pdf_fidelity.py:1-9`:22 案例的 98.63 是"Kiln PDF→pdfium PNG vs **Kiln 自家 CPU PNG**"的自洽对拍;文本一致率对拍对象是正则抽取的 HTML 文本(`pdf_fidelity.py:66-82`)。**闭环里没有浏览器真值。**
- `fidelity.py:50-55`:尺寸不一致时裁到共同区域再算分——**尺寸回归被静默吞掉**,而"导出尺寸错"恰是用户报告的第一异常。
- `bench-history.json` 自 2026-09-13 停更;README 引用 98.63 时未标注自洽口径。

## 3. 能力缺口矩阵(验收集 × 车道 K)

验收参考项目盘点结论:**26 个 HTML 全部纯 CSS、零 `<script>`**(echarts/gsap 在 vendor 里但无引用),难点全在 CSS/字体/布局:

| 验收项目 | 画布/规模 | 杀伤车道 K 的特性 |
|---|---|---|
| 1.易拉宝 | 2362×5906,scale2 → 4724×11812 | 超大画布内存;6 个内联 SVG 图标;fonts/ 缺失(PuHuiTi/思源宋未附) |
| 2.长图海报 | 无固定高,内容高 1740×19418(参考 PNG 6.32MB) | **20 处 grid**;fixed 伪元素扫描线/网格;3 组 @keyframes 需定格;glow/等宽混排 |
| 3.A4海报 | 1240×1754 ×2 页(正反面) | mask-image 渐变点阵;radial-gradient;`font-variation-settings:'wght' 900` 可变字体 |
| 4.节日海报×2 | a4p 1240×1754 | `mix-blend-mode:overlay/screen`;feTurbulence 噪点(SVG data URI);`backdrop-filter:blur`;`background-clip:text` 金字;`repeating-conic-gradient` 放射光+mask |

## 4. 架构方案:双车道导出(ADR-0020)

### 4.1 车道定义与路由

| | 车道 B(浏览器,Browser lane) | 车道 K(自研,Kiln native lane) |
|---|---|---|
| 渲染器 | 系统 Edge/Chrome(headless,CDP) | vb_layout(taffy)+ vb_render(tiny-skia) |
| 职责 | **对外交付的 PNG/JPG/PDF/AI**(保真优先) | 无浏览器环境兜底;编辑器实时预览;动画逐帧直出 |
| PDF 文本 | Chrome 原生真文本(Type0 子集嵌入+ToUnicode) | 现有 CIDFontType2 链路(修复拉丁嵌入后保留) |
| 保真承诺 | G1/G2 门禁背书 | 显式 WARNING:`degraded_engine: kiln-native`,文档明示分差 |
| 选路 | `--engine auto`(默认):浏览器可用→B,不可用→K+WARNING | `--engine native` 强制 |

与 ADR-0001 的关系:**修正而非推翻**——场景图/文档模型仍自研(编辑能力的根基);浏览器只承担"栅格化与打印"这一层,等价于把 Skia 当作渲染后端,而不是把产品架构让给 Electron(ADR-0009 的顾虑不成立:无 JS 执行、无常驻浏览器,进程内一次性调用后即退出)。

### 4.2 PNG 车道 B:Rust 原生 CDP + WPI 捕获协议十要素移植

新增 crate `vb_browser`(建议依赖 `chromiumoxide`;备选 `headless_chrome`,再不行手写 WebSocket 子集——CDP 用到的面很小)。浏览器发现顺序:`--browser-path` 参数 → `VB_BROWSER_PATH` 环境变量 → Edge stable 系统安装路径 → Chrome → 不可用即回落车道 K。**版本与通道锁定写入验收报告**(同版 Edge 才有同款 Skia 光栅)。

必须完整移植的 WPI 十要素(附录 A 有行号映射表):load+networkidle 等待、视口只定宽不撑高(100vh 保护)、`deviceScaleFactor` 原生倍率(非事后放大)、`captureBeyondViewport` 单拍优先/超限分块滚动拼接、fonts.ready+懒加载转 eager+img.complete 资源等待、滚动触发 reveal、有限动画 finish 定格、视觉稳定性哈希兜底、omit_background 透明/白底展平、rAF 节流+reduced-motion。

两个关键工程决定:

1. **直接渲染源 HTML,不走 Document 往返。** `kiln-cli export` 的输入就是 HTML 工程,起本地静态 HTTP 服务(移植 WPI StaticServer 的文件头与目录索引行为)后交给浏览器。import 往返的损失(白名单规范化、kiln import v1 近似取色)不阻塞导出保真;往返质量另行由 round-trip 门约束(§5.2 备注)。
2. **尺寸语义与 WPI 对齐:宽度 = 视口宽,高度 = 实测 scrollHeight;scale = deviceScaleFactor。** 物理像素 = CSS 尺寸 × scale,输出 PNG 无 pHYs(72dpi 解释),与 WPI 完全一致——G1 尺寸门才能逐例严格相等。

### 4.3 PDF 车道 B:printToPDF(screen 媒体)+ 后处理

协议(全部有 WPI `pdf_exporter.py:12-68` 先例背书):

1. `Emulation.setEmulatedMedia({media:"screen"})`——所见即所得,避免 print 样式表改版。
2. `Page.printToPDF`:landscape=false,printBackground=true,margin 四边 0,scale=1,`paperWidth=w/96` 英寸、`paperHeight=h/96` 英寸(MediaBox 即画板 CSS 像素,96dpi 约定)。
3. 长图(高 >2400px):先试单页大纸;若 Chrome 拒绝/渲染异常,回退 WPI 同款分页(零间距多页),验收以"逐页拼接后 vs PNG"计分。
4. 多页工程(3.A4 正反面):两 HTML 依文件名序各生成一页,合并单 PDF。

后处理(新增 `vb_kiln/src/pdfpost.rs`,依赖 pdf-writer 或 lopdf):

- MediaBox 归一为整数像素、/Rotate 0、去除 Chrome 冗余元数据;
- **字体嵌入审计(G5)**:遍历字体描述符,发现未嵌入即拒绝出片(Chrome 车道 B 天然全嵌入,此门同时防车道 K 的 Helvetica 回流);
- 可选增强(Stretch,不阻塞验收):按 `vb-layer` 注释锚点建 OCG 可选内容组,映射 Illustrator 图层。

### 4.4 AI:PDF 兼容流的现实边界

联网调研结论(附录 C 来源):现代 .ai = PDF 兼容流 + 私有 PGF 数据;PGF 无公开规范,**无任何第三方库可写**;开源界通行做法(Inkscape 官方立场一致)即"生成 PDF 改后缀 .ai",Illustrator 可正常打开编辑其中矢量与文本。Kiln 现有 `postscript.rs:52-67` 的 `%AI9_PrivateDataBegin` 头路线**保留且已是最优解**,本轮工作:

- AI = 车道 B PDF 流 + AI9 头,逐字节兼容 G2/G3 门禁;
- 可编辑性检查表(§5.2):真文本可选中改字、路径可选可改色、渐变保持矢量(车道 B 下 Chrome 原生 shading)、栅格降级区域占比 ≤ 阈值;
- 文档与 SKILL.md 明示边界:无 PGF 即无 AI 原生图层面板语义(除非 OCG 增强),这不是缺陷而是格式现实。

### 4.5 保真降级策略:不可矢量化效果 → 局部位图

优先级裁定"保真度>可编辑性>转换速度"落到 PDF 上的执行策略,即 PDF 透明度模型的局部拼合(Adobe transparency flattener 与 Skia SkPDF 同款):

1. 浏览器布局/绘制命令中,**能矢量的全部矢量**:文字(真文本)、边框、path、可映射渐变;
2. **不可矢量化的层**(复杂 blend、filter 链、feTurbulence、backdrop-filter)由 Chrome 自动栅格化为带 alpha 的图像 XObject + SMask 软蒙版,**原位放置、周围矢量文本不动**;
3. 降级位图采样倍率 ≥ deviceScaleFactor(即 scale=2 工程的降级位图至少 2x),保证印刷放大不糊;
4. 报告输出"栅格化区域占比"指标,超阈值(建议 30%)时 WARNING 提示可编辑性受损——把 trade-off 显式交给用户,而不是静默决定。

### 4.6 部署与开源约束

- kiln-cli 仍是**单二进制**,CDP 客户端为纯 Rust 依赖,不引入 Python/Node/Playwright;
- `selfcheck` 子命令扩项:浏览器发现→空页截图→printToPDF 三步探活,输出 `{browser_lane: ok|missing, engine_hint}`;
- 开源用户无 Edge/Chrome:文档明示装 Edge(免费)或用 `--engine native` 接受降级分;Release 页与 setup_kiln.py 同步说明;
- `wpi.rs` 的 Python 桥**保留为开发期对照工具**(基线渲染用),对外文档不再宣传为依赖。

## 5. 验收标准与门禁

### 5.1 指标定义(先立尺,后动刀)

| 指标 | 定义 | 备注 |
|---|---|---|
| MAD-score | `100 × (1 − MAD/255)`,MAD = 全像素 RGB 平均绝对差(沿用 `fidelity.py:47-60` 口径) | 双方必须**先过尺寸门**才计分 |
| 尺寸门 | 输出 PNG 物理像素 == 基线物理像素,逐例严格相等 | 不等即 FAIL 并报告 (w,h) 差值;禁止裁共同区 |
| G2/G3 对拍对象 | pdfium(本机 `E:\Tools\pdfium`)将 PDF 按画板像素栅格化 vs 车道 B PNG | 长图分页时先逐页拼接再计分 |
| G4 真文本 | 文本抽取(复用 `pdf_fidelity.py:66-82` 的 HTML 抽取口径)逐例全量匹配 | AI 同 PDF |
| G5 字体嵌入 | PDF 内全部字体描述符 Embed 未缺 | 含拉丁,杜绝 Helvetica 回流 |
| 环境指纹 | 报告记录:git SHA、Edge/Chrome 版本、pdfium 版本、字体清单、缺字体降级标记 | 同版浏览器才可复现同分 |
