# 09 · 工程架构与目录结构

> 单一真相 = `Document`；一切变更 = `Command`；渲染只读。
> 这条规则同时解决：Undo/Redo、Agent 回放、崩溃恢复、UI 一致性。

---

## 一、仓库结构

```
E:\平日资料\GitHub\VellumBench\
├── Cargo.toml                 # workspace
├── crates/
│   ├── vb_app/               # 入口：窗口、主循环、装配
│   ├── vb_ui/                # egui 面板、工具栏、对话框、主题
│   ├── vb_doc/               # 场景图、命令、Undo、.vbdoc 读写 ⭐核心
│   ├── vb_html/              # HTML 解析 / 序列化（canonical）
│   ├── vb_css/               # CSS 白名单、属性表、值解析与生成
│   ├── vb_layout/            # Taffy 封装、盒模型计算
│   ├── vb_render/            # wgpu/Vello 渲染、文本、图像、离屏导出
│   ├── vb_tools/             # 工具状态机（依赖 vb_doc::Command）
│   ├── vb_export/            # 导出管线、WPI 桥接
│   ├── vb_agent/             # CLI / MCP / 文件监听 / patch
│   ├── vb_platform/          # 窗口(winit)、文件对话框、剪贴板、字体枚举
│   └── vb_common/            # 几何、颜色、单位、StableId、工具函数
├── assets/                    # 图标、字体、内置示例、键位默认表
├── i18n/                      # zh-CN.ftl / en.ftl（含术语禁用表扫描目标）
├── tests/                     # roundtrip 语料、渲染快照、基准
├── tools/                     # build.ps1 / build.py（打包 + 冒烟 + 归档）
└── docs/                      # 本文档集副本
```

**依赖方向（禁止反向）**：
```
vb_app ──▶ vb_ui / vb_tools / vb_agent / vb_export
                  └──────▶ vb_doc ──▶ vb_html / vb_css / vb_layout
vb_render ◀──（只读消费）── vb_doc
```
`vb_render` **不得**修改 `Document`；`vb_doc` 不得依赖任何 GPU/UI crate（保证可无头测试）。

## 三、线程模型

| 线程 | 职责 |
|---|---|
| **主线程** | 输入处理 → 命令应用 → 布局 → 渲染编码 → 提交 GPU → UI |
| rayon 池 | Vello 场景片段编码、导出画板并行、图像解码 |
| 后台 I/O | 文件监听、sidecar 通信、自动保存、字体/资源加载 |
| FFmpeg / WPI | 子进程 |

**规则**：`Document` **只在主线程写**；后台线程通过 `mpsc` 提交 `Command` 或 `Query`，不得持锁访问文档。渲染器每帧只读快照（`&Document`，无需锁）。

## 四、命令模式（Undo / Redo / 回放）

```rust
pub trait Command: Send + Sync {
    fn apply(&mut self, doc: &mut Document) -> Result<ChangeSet>;
    fn revert(&mut self, doc: &mut Document) -> Result<ChangeSet>;
    fn label(&self) -> String;             // 编辑菜单显示"撤销 移动对象"
    fn kind(&self) -> CommandKind;         // 用于合并
    fn target(&self) -> Option<NodeId>;    // 用于合并
    fn to_patch(&self) -> Option<PatchOp>; // 序列化 → 给 Agent / 回放 / 崩溃恢复
}

pub struct ChangeSet {
    pub nodes_added: Vec<NodeId>,
    pub nodes_removed: Vec<StableId>,
    pub style_dirty: Vec<NodeId>,
    pub layout_dirty: bool,
    pub structure_dirty: bool,
    pub rev: u64,
}
```

| 机制 | 规格 |
|---|---|
| Undo 栈 | `VecDeque<Box<dyn Command>>`，内存上限 200MB，超出溢出到 `.vbdoc/history/` |
| 合并 | 同 `kind` + 同 `target` + 500ms 内 → 合并（数值框连续输入不刷栈） |
| 事务 | `CompoundCommand`（一次 patch = 一条 undo） |
| 重放 | 命令可序列化 → 崩溃恢复、Agent 回放、宏（v2） |
| 命名 | 撤销菜单显示「撤销 移动对象」（带具体命令名，与 AI 一致） |

**命令 ID 表** `commands.yaml`（单一真相）：
```yaml
- id: object.group
  label: 编组
  menu: 对象
  keys: { win: "Ctrl+G", mac: "Cmd+G" }
  undoable: true
  expose_to_agent: true
```
快捷键、菜单、面板按钮、CLI、MCP、宏共用此表。启动时校验：所有绑定指向存在的命令 id，键位冲突报 warning。

## 五、事件与刷新

命令应用后广播 `DocEvent::Changed(ChangeSet)`，观察者：

| 观察者 | 反应 |
|---|---|
| 渲染器 | 更新脏标记 → 重建静态层 |
| UI 面板 | 重读需要的数据（egui 立即模式天然每帧读） |
| 自动保存 | 重置 60s 计时器 |
| HTML 同步 | 若开启"自动同步 HTML"→ 去抖 1s 后原子写盘 |
| Agent watcher | 抑制"外部修改"提示（自己写的不算外部修改） |

## 六、持久化

| 文件 | 内容 | 时机 |
|---|---|---|
| `MyProject.vbdoc` | ZIP：`project.json` + `guides.json` + `history/` + `cache/` | `Mod+S`、自动 60s、退出 |
| `index.html` + `styles/` + `assets/` | HTML 产物 | `Mod+S`（或开启自动同步） |
| `%APPDATA%\VellumBench\config.toml` | 全局偏好、最近文件、键位方案、导出预设 | 变更即写 |
| `MyProject.vbdoc.autosave` | 崩溃恢复 | 60s |

**原子写**：写临时文件 → `fs::rename` 覆盖（避免断电损坏）。
**HTML 同步**：默认「保存时同步」；Agent 场景建议开「自动同步」（去抖 1s，且写入时先比对内容避免无谓 mtime 变化触发自身监听）。

## 七、错误处理与日志

- 库层 `thiserror` 定义 `VbError::{Io, Parse, Gpu, Conflict, Unsupported{prop, element}}`
- 用户可见错误统一走「提示条 + 日志详情」，**不弹崩溃对话框**
- `Unsupported` 错误专门驱动「冻结块」与「不支持提示」（见 01/04 篇）
- 日志：`tracing` + `tracing-appender`，路径 `%LOCALAPPDATA%\VellumBench\logs\`，按天滚动，保留 7 天
- 崩溃：`panic` 钩子 → 写 `crash-<timestamp>.log` + 提示恢复自动保存

## 八、i18n 与文案

- `i18n/zh-CN.ftl` / `en.ftl`，键名 = 命令 id 或 `panel.xxx.field`
- **术语 lint**：CI 扫描文案文件，命中禁用词表（01 篇第七节）直接失败
- **覆盖率门禁**：新增 UI 字符串必须有中英双语（见 10 篇）

## 九、代码规范

| 项 | 规则 |
|---|---|
| 格式 | `rustfmt.toml`（`max_width=100`, `imports_granularity=Module`） |
| Lint | `clippy -D warnings`（CI） |
| 颜色 | 禁止渲染/UI 代码出现颜色字面量，一律 `--vb-*` 令牌（lint 检查） |
| 单位 | 内部只准出现 px；任何其他单位必须经 `units.rs` 转换 |
| 角度 | AI 语义（逆时针正），仅序列化层取负；禁止散落转换 |
| 模块 | 每个 crate 的 `lib.rs` 顶部写职责与依赖方向 |
| 公开 API | 每个 `pub fn` 有文档注释（缺失则 `missing_docs` warning） |
| 提交 | Conventional Commits（`feat(render): …`），小步提交 |

## 十、构建与发布（沿用既有习惯）

```
编码 → 提交 → 取 short hash → 提版本号 → 更新 README/Cargo.toml
     → tools/build.ps1（cargo build --release + 打包 + 离线冒烟 + 归档）
     → 交付
```

- 产物归档：`E:\平日资料\构建\VellumBench\{semver}-{short_hash}\`
- 包内容：`VellumBench.exe` + `assets/` + `WPI-noGUI-cli.exe`(或 sidecar) + `ffmpeg.exe` + `VERSION.txt` + `README.md`
- 不随附浏览器（与 WPI 一致，首次使用提示）
- 小版本（0.x.y）简化校验：跑通 + 冒烟；大版本走完整门禁（见 10 篇）
- GitHub：仅推送 `crates/` + `assets/` + 元数据；`tests/` 与 `tools/` 排除（沿用 MomentShift 策略）

## 十二、验收点

- [ ] `cargo depgraph` 检查无反向依赖（脚本化，CI 跑）
- [ ] `vb_doc` 可在无 GPU/无窗口环境下编译并跑全部测试（headless）
- [ ] 命令表 `commands.yaml` 覆盖 100% 菜单项与工具操作
- [ ] Undo 栈：连续拖动只产生 1 条；Compound 命令一次撤销
- [ ] 崩溃恢复：kill 进程后重启，能恢复到最近 60s 内状态
- [ ] 所有 crate 有 `lib.rs` 职责注释
