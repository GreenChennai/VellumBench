# 10 · 性能预算与质量门禁

> 性能是**可感知功能**，不是优化项。达不到预算 = 功能缺失，不允许"以后再优化"。

---

## 一、性能预算（硬指标）

| 场景 | 预算 | 测量方式 |
|---|---|---|
| 冷启动（空文档，首帧可见） | ≤ 1.5s | 进程启动 → 首帧 present |
| 打开 5 万对象文档 | ≤ 5s | |
| 打开 1000 对象普通文档 | ≤ 2s | |
| **拖动对象**（1 万对象文档中） | 重绘 ≤ 8ms（125fps） | GPU timestamp |
| **平移 / 缩放**（5 万对象） | ≥ 60fps 稳定 | 帧时间 P95 ≤ 16.6ms |
| **钢笔绘制跟手** | 输入 → 显示 ≤ 16ms | 高刷屏下 ≤ 8ms |
| 输入延迟（按键 → 画面） | ≤ 16ms | |
| 文本输入（大段中文） | 单字符 ≤ 8ms | |
| 首帧（文档打开后可见内容） | ≤ 100ms | |
| 内存（5 万对象 + 200 图） | ≤ 1.5GB；显存 ≤ 1GB | |
| 导出 PNG 1440×900 @1x | ≤ 300ms | 原生引擎 |
| 导出 PNG @3x（4320×2700） | ≤ 1.5s | |
| 批量导出 50 画板 @2x | ≤ 60s | 原生引擎 |
| 浏览器引擎导出（sidecar 热实例） | ≤ 800ms/次 | 冷启动 ≤ 6s |
| 保存（+HTML 同步） | ≤ 500ms（1000 对象） | |
| 撤销/重做 | ≤ 50ms | |
| 安装包体积 | ≤ 120MB（不含浏览器） | |

**目标硬件**：AMD RX 9070 GRE / R7 级 CPU / 32GB / NVMe / 1440p。
**最低硬件**（需降级但仍可用）：Intel UHD 核显 / 8GB —— 自动进入「性能模式」。

## 二、基准语料（Benchmark Corpus）

`tests/bench/` 内置 5 个标准场景，每次性能改动前后必跑：

| 场景 | 内容 |
|---|---|
| `B1-small` | 1 画板，200 对象（矩形/文本/图片混合） |
| `B2-medium` | 4 画板，5000 对象，含 20 张图 |
| `B3-large` | 1 画板，50000 矩形 |
| `B4-path` | 5000 条复杂贝塞尔路径（每条 50+ 锚点）+ 渐变描边 |
| `B5-text` | 2000 个中文文本对象（测图集与整形） |
| `B6-real` | 3 个真实落地页（从 roundtrip 语料取） |

度量：帧时间 P50/P95/P99、编码耗时、布局耗时、显存、导出吞吐。
结果存 `bench-history.json`，**回归 > 10% → CI 失败**。

## 三、性能模式与自动降级

| 触发 | 降级动作 |
|---|---|
| 帧时间 P95 > 20ms 持续 2s | 提示「启用性能模式？」；自动：关闭实时阴影/模糊预览 |
| 可见对象 > 50k | 关闭渐变细节、文本 LOD 阈值提高 |
| 缩放 < 20% | 文本/阴影省略为色块 |
| 显存 > 预算 90% | LRU 换出纹理，用缩略图占位 |
| 无 Vulkan | 依次 Metal → DX12 → GL；GL 下禁用 MSAA |
| 设备丢失 | 重建 device + 重传资源 + 恢复文档（不丢未保存内容） |

用户可手动：`设置 → 性能` → 关/自动/最高质量/最高性能。

## 四、质量门禁（CI）

沿用「大版本全门禁、小版本简化校验」的既有习惯：

### 大版本（x.0 / 重大重构）— 7 项全过

| # | 门禁 | 内容 | 失败条件 |
|---|---|---|---|
| 1 | **格式与 Lint** | `cargo fmt --check` + `clippy -D warnings` | 任一警告 |
| 2 | **测试** | 单元 + 属性测试 + 集成；覆盖率 ≥ 70%（核心 crate ≥ 85%） | 失败或低于阈值 |
| 3 | **往返语料** | 100 个 HTML：L0 不损坏 100%、L1 幂等 100% | 任一失败 |
| 4 | **渲染快照** | `vello_cpu` 输出与基线 PNG 比对（容差 2/255） | 差异超阈值 |
| 5 | **性能基准** | B1–B6 对比上次基线 | 回归 > 10% |
| 6 | **文案与术语** | 术语禁用表扫描 + i18n 双语覆盖率 100% | 命中禁用词或缺翻译 |
| 7 | **输出校验** | 输出 HTML 过 W3C Nu Validator（无 error）+ `prettier --check` | 任一 error |

### 小版本（0.x.y）— 3 项

`1 格式与 Lint` + `2 测试` + **离线冒烟**（启动 → 打开示例 → 画矩形 → 保存 → 导出 PNG → 关闭，全程退出码 0）。

### 手工门禁（每次发布前）

- 交互 checklist（快捷键 40 条 + 工具行为 30 条）
- AI 老用户盲测（3 人，5 项任务）
- 导出格式逐一验证（PNG/JPG/SVG/PDF/GIF/MP4/HTML）

## 五、CI 流水线

```yaml
on: [push, pull_request]
jobs:
  windows:
    - cargo fmt --check
    - cargo clippy -- -D warnings
    - cargo test --workspace
    - cargo run -p vb_roundtrip          # 语料库
    - cargo run -p vb_render_snapshots   # vello_cpu 无 GPU
    - python tools/check_i18n.py          # 术语 + 覆盖率
    - python tools/validate_html.py       # W3C + prettier
  bench:
    if: github.event_name == 'push' && contains(github.ref,'main')
    - cargo bench -- --save-baseline ci
    - python tools/bench_compare.py --tolerance 10
```

- 渲染快照用 **CPU 后端**（`vello_cpu`）→ 无需 GPU runner，结果稳定可复现
- GPU 相关（device-lost、驱动兼容）靠**手工矩阵测试**（本机 RX 9070 GRE + 一台核显机）
- 构建产物：GitHub Actions 发布 Release（zip）

## 六、版本与发布流程

```
1. 编码 + 单元测试
2. git commit（Conventional Commits）
3. git rev-parse --short HEAD → short_hash
4. 提版本号（Cargo.toml / VERSION.txt / README 徽章）
5. tools/build.ps1  →  release 构建 + 打包 + 离线冒烟 + 归档
6. 归档：E:\平日资料\构建\VellumBench\{semver}-{short_hash}\
7. 手工冒烟（真实 GPU 环境）：启动 / 打开示例 / 编辑 / 保存 / 导出全格式
8. 交付（大版本才 push tag + GitHub Release）
```

- 小版本（0.x.y）：步骤 1–7，不推 tag
- 大版本（x.0.0）：全步骤 + 7 项门禁 + Release
- **不主动推送 GitHub**（沿用既有策略，本地归档为主）

## 七、内置诊断

| 工具 | 用途 |
|---|---|
| 性能面板（`设置 → 性能`） | FPS、帧时间、编码/布局耗时、可见对象数、显存 |
| `--diag` 启动参数 | 输出环境报告：GPU/后端/驱动版本/特性支持/内存 |
| `vellum-cli --selfcheck` | 无头自检：打开示例 → 导出 PNG → 校验产物（对齐 WPI 的 `--selfcheck` 习惯） |
| 日志 | `%LOCALAPPDATA%\VellumBench\logs\`，`RUST_LOG=vb_*=debug` |
