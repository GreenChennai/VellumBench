# 13 · ADR 与风险登记

> ADR = Architecture Decision Record。每条记录：背景 → 候选 → 决策 → 理由 → 后果。
> **决策一旦记录，修改必须新增 ADR 而不是改旧的**（保留历史，便于回溯）。

## ADR-001：文档渲染用自研场景图，而非嵌入浏览器引擎

| | |
|---|---|
| **背景** | 需要"编辑 HTML 文档"的能力，最省力的是嵌入 Chromium |
| **候选** | A) CEF/Chromium 嵌入；B) Servo；C) Blitz（wgpu+Stylo+Taffy）；**D) 自研场景图 + CSS 白名单** |
| **决策** | **D**（辅以 Chromium 旁路做真值校对与导出） |
| **理由** | A：200MB+ 体积、进程间合成与输入路由复杂、无法做 AI 式手柄/锚点的高频覆盖层；B/C：CSS 覆盖与生态不足，且无法保证与 Chrome 一致，仍是"另一个浏览器的行为"；D 让**文档模型成为一等公民**，可精确控制 round-trip、可无损序列化、可被 Agent 寻址 |
| **后果** | 必须长期投入 CSS 白名单扩展；不可避免地存在"自绘与浏览器不一致"，用**冻结块 + 校对视图**把这个风险显式化、可测量 |

## ADR-002：渲染用 wgpu + Vello，而非裸 Vulkan / Skia

| | |
|---|---|
| **候选** | A) 裸 Vulkan（ash）；B) Skia(Vulkan 后端)；**C) wgpu + Vello**；D) Qt Quick |
| **决策** | **C** |
| **理由** | A 需 5000+ 行样板且无跨平台回退；B 构建重、Rust 绑定滞后、无并行编码；D 与 UI 框架绑定且 2D 路径性能一般。C：Vulkan/Metal/DX12/GL 全覆盖、Vello 的 GPU 全量光栅 + 并行编码适合海量路径、与 egui 共享 device |
| **后果** | 依赖 linebender 生态（演进中，API 可能变化）；文本需自行集成 Parley；`vello_cpu` 用于 CI 渲染快照 |

## ADR-003：UI 用 egui，而非 Qt / Tauri / 自绘

| | |
|---|---|
| **候选** | A) PySide6/Qt（熟悉）；B) Tauri（Web 前端）；C) 自绘 immediate-mode；**D) egui** |
| **决策** | **D** |
| **理由** | A 与 Rust 渲染核心跨语言、两个 GPU 上下文；B Web 技术栈的 DOM 开销与 GPU 合成开销；C 工作量巨大；D 与画布共享同一 wgpu device、单窗口同帧合成、Rust 原生、工具型表单面板够用 |
| **后果** | 复杂自定义控件（图层树拖拽、渐变编辑器）需自绘；外观需自行做 AI 风格主题（可接受，可控） |

## ADR-004：CSS 用「白名单 + 冻结块」，而非追求完整 CSS

| | |
|---|---|
| **候选** | A) 完整 CSS（嵌入浏览器）；**B) 分级白名单 + 冻结块 + unknown 保底** |
| **决策** | **B** |
| **理由** | 完整 CSS = 重写浏览器；白名单覆盖 80% 场景即可交付价值，其余以"不可编辑但不损坏"的姿态存在 |
| **后果** | 必须维护属性表与测试；必须有清晰的用户提示（冻结块/不支持提示），否则体验崩坏 |

## ADR-005：WPI 用「进程 → 常驻 sidecar」集成，而非嵌入或重写

| | |
|---|---|
| **候选** | A) PyO3 嵌入 Python；B) 用 Rust 重写导出链路；**C) CLI 进程调用 → 常驻 sidecar(JSON-RPC)** |
| **决策** | **C** |
| **理由** | A 构建复杂度翻倍、Python GIL 与版本耦合；B 重写"浏览器行为经验知识"（reveal-on-scroll、动画冻结、PDF 分页）纯亏；C 隔离崩溃、可复用浏览器实例、WPI 独立演进互不干扰 |
| **后果** | 需给 WPI 加 3 个参数（`--selector`/`--clip`/`--json`）；主程序必须能在 WPI 缺失时正常工作 |

## ADR-006：文本用 Parley + Swash（保留回退位）

| | |
|---|---|
| **决策** | 主用 Parley（布局/整形）+ Swash（光栅）+ 自建图集；抽象 `trait TextShaper` |
| **理由** | Rust 原生、与 Vello 同源、支持中文与复杂脚本 |
| **后果** | 若质量/性能不达标，回退路径：`fontdue`/`skia-safe` CPU 光栅进图集（接口已抽象，改动局部） |

## ADR-007：单位、坐标、角度的全局约定

| 项 | 决策 |
|---|---|
| 内部单位 | 一律 **px**（CSS px）；显示单位可切换 |
| 坐标 | Y 轴**向下**（与 CSS 一致）；元素坐标相对所属画板 |
| 角度 | 内部 AI 语义（逆时针为正）；**仅序列化层取负**写入 CSS |
| 精度 | 计算 f64，输出 ≤ 4 位小数并去尾随 0 |

**理由**：避免散落转换导致的方向/单位 bug。**后果**：必须写单元测试锁死（≥ 100 条用例）。

## ADR-008：Undo 用命令模式，而非快照；不提前引入 CRDT

| | |
|---|---|
| **决策** | `Command{apply, revert}` + ChangeSet；Undo 栈内存上限 200MB，溢出写盘。**v3 再评估 CRDT** |
| **理由** | 命令模式同时满足 Undo、Agent 回放、崩溃恢复、事务；过早引入 CRDT 会污染文档模型设计并显著增加复杂度 |
| **后果** | v3 做协作时需为 CRDT 改造（已预留：`sid` 稳定 id 天然适合 CRDT 键） |

## ADR-009：主语言 Rust，不用 Electron / Tauri

**理由**：GPU 控制粒度、内存占用、启动速度、与 wgpu 生态同源。
**后果**：开发速度低于 Web 栈；靠 Agent 辅助编码与组件复用弥补。

## ADR-010：HTML 是源格式，不设私有锁

**决策**：`.vbdoc` 只是"编辑器状态容器"，随时可丢弃；`index.html` 永远是可独立使用的完整产物。
**理由**：见 00 篇 Q2（往返与不锁定）。
**后果**：编辑器私有信息（网格/参考线/历史）不能进 HTML，只能存 `.vbdoc`；某些精确还原需要额外数据 → 用 `data-vb-*` 属性承载（可选输出）。

## ADR-011：定位策略提供「矢量模式 / 流式模式」双开关

**决策**：默认**矢量模式**（绝对定位，像 AI）；提供流式模式（flex 文档流，代码更"前端友好"）；可混合（容器绝对定位、内部流式）。
**理由**：AI 用户要自由摆放；前端用户要可维护代码。二者不可兼得，做成显式开关。
**后果**：两种模式下的序列化路径不同，测试需覆盖。

## ADR-012：路径布尔方案（**待 Spike 5 结论填充**）

| 候选 | 状态 |
|---|---|
| `flo_curves` | 首选（纯 Rust、有 path 布尔与 offset） |
| `skia-safe`（仅 `Path::op`） | 备选（成熟但依赖重） |
| `vello_cpu` 光栅 + 矢量化 | 兜底（质量差） |

## 风险处置原则

1. **R5（范围膨胀）是头号杀手** —— 任何新想法先进「不做清单」排队。
2. **R1/R6 靠"可测量"解决** —— 语料库与校对视图让风险变成数字。
3. **R2/R3/R4 靠 Spike 前置** —— 花 2 周验证，避免半年后返工。
4. 每次版本评审更新本表（新增行不删旧行，标注处置结果）。

# 提交与文档纪律（Commit & Doc Discipline）

> 来源：14 篇 §7.2 / §7.3。**本节是纪律，不是建议** —— 违反它，后续所有判断的输入都是脏的。

## 一、为什么要有这一节

历史问题：8 个 commit 全在同一天，最后一条声称交付 `v0.7 + v1.4 + v1.0` 三类内容，而代码实际范围远小于声称。
**虚标的版本号会污染所有后续判断** —— 当你说不清自己站在哪，就没法决定下一步做什么。

## 二、commit message 四条规则

| # | 规则 | 反例 |
|---|---|---|
| 1 | 只描述本次改动本身，**不写版本里程碑**（里程碑归 `docs/design/` 管） | ❌ `feat: v0.7 + v1.4 + v1.0` |
| 2 | **禁止一个 commit 混多层**；多层拆成可独立回滚的多条 | ❌ 上条应拆成 3 条 |
| 3 | 影响 README 状态表的改动，**同 commit 内**更新状态表 | ❌ 加了功能却不改状态表 |
| 4 | 提交前自检一句话：「有人 checkout 这个 commit 并按 README 操作，会得到什么？」答不出来 = message 写虚了 | — |

## 三、文档与代码同步规则

| 触发 | 动作 |
|---|---|
| 新增命令 / 工具 | 同 commit 更新 `commands.yaml` + 14 篇第 4 章 |
| 新增主题令牌 | 同 commit 更新 `vb_ui::theme` + `docs/design/assets/vb-ui-tokens.json` + 14 篇 §3.2 |
| 与 Illustrator 行为有意不一致 | 同 commit 写进 02 篇 §六 差异表，**必须写原因** |
| 新增依赖 | 同 commit 在 `docs/deps.md` 记一行（用途 / 体积 / 许可 / 替代） |
| 文档里的 ⚠️待实测 | 有条件时真机核对 Illustrator 并更新（02 篇 §八 首项） |
