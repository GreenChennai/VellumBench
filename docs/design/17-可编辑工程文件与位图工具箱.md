# 17 · 可编辑工程文件质量 + 位图工具箱(v0.6)

> 用户反馈三轮:① AI 打开工程文件满屏剪切蒙版;② 字体全部转曲且逐字碎裂;
> ③ 公众号封面等系列物料的纯像素后处理应下沉为 Rust 位图工具箱。
> 日期:2026-09-17 · 状态:已接受并落地

## 一、工程文件质量(PDF/AI 编辑体验)

### 诊断

AI(Illustrator)打开 Kiln 导出的 PDF/AI 时满屏剪切蒙版、字体转曲、逐字碎裂,
根因在**内容流发射策略**而非字体嵌入:

1. 每个 DrawItem 均包裹 `q…Q`(图形状态隔离)——AI 导入时每对 q/Q + cm
   呈现为一个剪切蒙版组;一张海报 25+ 对 q/Q 就是 25+ 层蒙版
2. 旋转项额外嵌套三层 `cm`(平移→旋转→平移回去)——AI 对嵌套 cm
   呈现为嵌套剪切蒙版
3. 文本跟随外层 `q cm Q` → AI 把文本装进剪切蒙版组
4. v0.4 遗留:非 CJK 文本走 Helvetica base-14(未嵌真实字体),
   CJK 走逐字形轮廓(`outline_text_pdf`)——逐字形矢量 = 逐字碎裂

### 决策

1. **`q/Q` 只在旋转时使用**:填充/描边/文本不再包裹——所有操作符
   自行设置状态(rg/RG/Tf),无状态泄漏。旋转时仍需 `q cm Q`
   (坐标系统隔离),但只影响旋转项
2. **文本永不 `cm`,旋转进 `Tm`**:`Tm` 是完整的 2×3 矩阵,可编码
   任意旋转——AI 里文本对象是纯文本,不再被剪切蒙版包裹
3. **统一 CID 真文本**:CJK 与 Latin 全走 Type0/Identity-H/子集嵌入
   (font_data_for 可解析时);轮廓化仅在字体完全不可得时兜底
4. **同段文本一串 Tj**:per-line + per-segment(色彩变化处分段);
   整句/整行在同一 BT/ET 块内,`Tm` 逐段定位——AI 里一段连续文本
   = 一个文本对象,编辑不需要逐字

### 量化结果

| 指标 | v0.5.0 | v0.6 |
|---|---|---|
| 内容流 `q` 数 | 25 | **1**(仅旋转贴纸) |
| 内容流 `Q` 数 | 32 | **1** |
| 剪切蒙版来源(`cm` on text) | 有 | **0**(文本用 Tm) |
| 中文可提取 | ✅ | ✅ |
| Latin 字体嵌入 | ❌(Helvetica base-14) | ✅(CID 子集) |

### 权衡

- 无 q/Q 包裹意味着图形状态(颜色/线宽)依赖每项自行设置——当前
  每项均显式 rg/RG,无泄漏;若后续加入全局透明度(GS)需恢复包裹
- 旋转文本用 Tm 旋转基线,在 AI 中的文本框轴向为旋转后方向——
  与 CSS rotate 语义一致,但用户在 AI 中拖动时坐标系非轴对齐(预期行为)
- Latin base-14 兜底保留(极小概率:字体完全不可解析时文本仍可选)

## 二、位图工具箱(kiln-cli img)

### 动机

系列物料的纯像素后处理(公众号合并封面、长图拼接、封面裁切、模糊背景)
此前散落为多个 Python/Pillow 脚本;用户反馈"不要为了一个系列单独做好几个脚本"。
下沉到 Kiln 后:一次构建,`Kiln-noGUI-CLI.exe img <op>` 任意脚本/Agent 直接调用。

### 子命令

| 子命令 | 功能 | 参数要点 |
|---|---|---|
| `img crop` | 裁剪 | `--box l,t,r,b` 像素;或 `--trim #bg` 自动去同色边 |
| `img stitch` | 拼接 | `--inputs a,b,c` `--direction vertical\|horizontal` `--gap` `--bg` `--align` |
| `img blur` | 高斯模糊 | `--radius`;`--box` 区域模糊(box 内模糊 box 外保持) |
| `img pad` | 画布填充 | `--width --height --bg --align` |
| `img info` | 宽高信息 | — |

纯 image crate,零新增依赖。产出单行 JSON(同 export 约定)。

### gzh_cover.py 合并封面改造

`merge` 子命令的 Pillow 等高拼接改为 `kiln-cli img stitch --direction horizontal`;
删除 PIL 依赖路径。HTML 封面生成不变(设计能力在 HTML/CSS 侧)。

## 三、不在本轮做

- 渐变模糊(方向性/渐变 alpha 模糊)——image crate 无现成 API,自行实现
  成本高,当前以 uniform blur + box 覆盖
- SVG 导入(usvg→kurbo)——延续 v0.5 延后决策
- AI 私有格式(PGF)——闭源格式不可逆向;PDF 兼容流 + CID 真文本已满足
  "可编辑文字 + 图层可视"核心诉求
