## 2 · P0 — 崩溃(2 条,批次 A 第一优先)

### P0-1 `order` op 作用于 root sid → `.unwrap()` panic,MCP server 整体死亡【实锤】
- **位置**:`crates/vb_agent/src/patch.rs:368`(`parent.unwrap()`),root 的 `parent` 为 `None` 但 `find_by_sid` 能搜到 root(root 有确定性短码 sid)。
- **触发**:MCP `vellum_apply_patch` 传 `{"op":"order","id":"<root sid>","to":"front"}` → panic → 无 `catch_unwind`,主循环被击穿,server 进程退出,客户端只能等超时;CLI 同样以 101 退出。
- **修法**:所有 op 的 `find_by_sid` 命中 root 时返回结构化 `PatchError`;补 MCP 层「未知 sid / 非法目标」回归测试。

### P0-2 GUI 用 Delete 键可把画板删光,随后任何创建操作 panic【实锤】
- **位置**:`crates/vb_app/src/app.rs:649`(`insert_target` 的 `.expect("文档至少有一块画板")`)+ `app.rs:1423`(`delete_selection` 无画板守卫)。
- **触发**:画板工具新建画板(自动选中)→ 按 Delete → 重复删光 → 切矩形工具单击 → panic。图层面板删除按钮有 `len() > 1` 守卫,Delete 键路径没有;导入 0 画板文档后绘图同样命中。
- **修法**:两层都补——`delete_selection` 拒绝删除最后一块画板(与面板守卫同语义);`insert_target` 空画板时自动落一块默认画板(双保险)。命令层 `Command::Delete` 对画板节点是否放行需在写失败测试时一并裁定并锁定。
